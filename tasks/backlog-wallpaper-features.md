> 一次性任务清单：做完一项勾一项；长期约定归 `AGENTS.md` 与 `tasks/decisions.md`。

## 一、壁纸后期滤镜

旧抽屉里有亮度、对比度、饱和度、色相偏移、电影暗角、胶片颗粒，外加一个预设下拉框。
它们只是抽屉预览图上的浏览器 CSS 滤镜；点"设为壁纸"时，值只被拼进提示文字，
`daemon_apply` 与配置里都没有对应的键，所以屏幕上画出来的壁纸从未受过影响。

### 要做的事

1. [ ] **定数据模型**（先于一切）：滤镜是**全局一份**，还是**每张壁纸一份**，或**每个显示器一份**。
   - 全局最简单：顶层 `filter.*` 键，与现有 `scale`、`fit` 同级。
   - 每张壁纸一份要有按路径保存的地方，配置结构、热重载和"重置为默认值"的语义都要重新设计。
   - 每个显示器一份可以挂在现有的 `outputs.<name>` 表下。
2. [ ] **配置键**（`crates/proto`）：亮度、对比度、饱和度、色相、暗角、颗粒，各带范围与默认值（默认值须等于"无效果"）。
   - 改了 `schema` 输出就是改了 app 与守护进程的契约；按 `AGENTS.md`，改动前后各导出一份 `niripaper schema` 做对比。
3. [ ] **着色器**（`src/scene.rs`，一帧的绘制在这里）：给最终合成加 uniform，亮度/对比度/饱和度/色相是逐像素运算，
   暗角按到中心的距离，颗粒要带时间种子（静态图上是否需要随时间变化，要先定）。
   - 静态图与视频走同一条路径，不要各写一份。
   - 过渡期间滤镜怎么处理（新旧画面都过滤，还是只过滤落定后的画面）要先定。
   - 改完用 `trprobe` 逐个效果出图看一眼（见 `AGENTS.md`），再 `daemon --trace` 实机跑一次。
4. [ ] **测量成本**：全屏每帧多几次采样和运算，视频壁纸与高分屏上要实测；默认值（全部无效果）时应当完全跳过，不付任何代价。
   测量方法见 `docs/verification.md`，不要拿 `--dump-stats` 和 `nvidia-smi` 的噪声下结论。
5. [ ] **界面**：回到壁纸抽屉或设置页，用"设置分组 + 设置行"加滑块，改了立即生效，值不是默认值时显示恢复默认。
   - 预设下拉框（旧界面有）要不要保留，等数据模型定了再说；预设只是一组滑块值，可以放在界面层。
6. [ ] **验证**：每个键用**非默认值**在真桌面上看一遍，确认确实画出来了（`AGENTS.md`："配置键写了但从未接上线"的教训）。

### 开放问题

- 滤镜与 `follow_wallpaper` 取色的关系：取色用的是原图还是滤镜之后的画面？（取色在前端从图像像素读，目前读的是原图。）

## 二、轮播列表

旧抽屉里的"加入轮播列表"只弹一条提示，没有任何实际作用。守护进程目前没有"壁纸轮播"这个概念
（`transition.selection` 的 rotate / random 是**过渡效果**的轮播，不是壁纸的）。

1. [ ] 先定义：轮播的是一个目录、一份手选列表，还是播放队列？间隔多久，按显示器分还是全局？
2. [ ] 守护进程与控制协议里加上对应的配置键和请求。
3. [ ] 界面：抽屉里的"加入轮播列表"随之恢复，并在某处能看到和管理这份列表。
