# 单一配置文件，只有 GUI 写

配置只有 `~/.config/niripaper/config.toml` 一个文件。守护进程**只读**它，GUI（未来的桌面应用）是唯一的写入者，用 `toml_edit` 做外科手术式改写（只替换被改的键，保留其余字节）并以"写临时文件再 `rename`"原子替换。

它取代了「`config.toml` + `config.d/*.toml` 按文件名排序深合并」那套分层机制（见下）。

## Considered Options

- **`config.d/` 分层合并，按文件名排序**（原设计，[ADR 0006](0006-config-d-directory-not-include.md)）：否决。文件名当优先级是**隐式规则** —— 要用户靠 `90-` 这种前缀推理谁赢，而这套机制服务的"多个写入者各占一份"在实际使用里只剩一个写入者（GUI）。
- **不排序，按 `read_dir` 顺序**：否决。`read_dir` 无序，等于"同一份配置两次启动可能合并出不同结果"，是不可复现的 bug，不是简化。
- **单一文件 + 一个写入者**：采用。

## Consequences

- **注释是这份文件的一部分，必须留住。** 它是逐键说明的数据源 —— 像 `center` 的示例坐标、`hold_ms` 为什么别用、`cubic_bezier` 为什么选那组值，`schema.about` 装不下（`about` 只有一行）。所以写入**必须**用 `toml_edit`；用 `toml` 反序列化再序列化回去会把这些注释全抹掉。实测：改两个键后 201 行 / 152 注释行**一字节不变**。
- **并发写不存在**：只有一个写入者。守护进程读到写了一半的文件也不会崩 —— 解析失败会保留正在运行的配置并打印原因。
- **原子替换正好复用现成机制**：`watch.rs` 本来就监视**目录**而不是文件，并认 `IN_MOVED_TO`（它的注释写着"编辑器多为写临时文件再 rename"）。GUI 的"临时文件 + rename"无需任何新机制。
- **`output` / `namespace` 不能热改**这条要求不变（重建 layer 表面代价太大），只是它现在只可能是 GUI 写错了，而不是"另一个工具的文件"。
- **作废**：ADR 0006、`docs/SPEC.md` 里的配置合并规则、`CONTEXT.md` 的 `config.d drop-in` 术语，以及两个测多文件覆盖的单测。
